# 邮报生成元数据标注设计

## 目标

在每日邮报标题区域之后，以低存在感的注释显示两项真实运行元数据：本期使用的生成模型，以及本封邮件完整生成流程的 token 总消耗。总消耗包含初稿调用和最多两次自动质量修复调用。该信息由运行器自动写入，模型不能自行填写或修改。

## 范围与非目标

本次只改变生成与投递前的元数据采集、正文注入和日志记录，不改变 11:00/23:00 调度、来源采集、去重规则、栏目要求、收件人或 SMTP 配置。不会在公开仓库保存运行时事件、提示词、邮件正文、凭据或 token 明细文件。

## 方案选择

### 采用：捕获 Codex JSONL 事件并在本地汇总

运行器为每次 `codex exec` 调用增加 `--json`，将 stdout 暂存到当前任务的私有临时文件；最终正文仍通过 `--output-last-message` 获取。每次初稿或修复调用完成后，将事件文件加入本次任务的列表。校验成功后，Python 元数据模块只读取这些临时 JSONL 文件，汇总 usage，再把注释写入待发送正文；任务结束时由现有 trap 删除临时提示词、最终稿和事件文件。

usage 解析只信任完成事件中的 usage 对象：优先使用 `total_tokens`；若当前 CLI 事件没有该字段，则用同一 usage 对象中的 `input_tokens + output_tokens` 计算。无效 JSON、无 usage 事件或字段不完整会被忽略；如果所有调用都没有可靠用量，则显示“本次总用量：暂不可得”，并在运行日志中明确记录，不猜测数字。模型名称使用运行器显式传给 Codex 的 `CODEX_MODEL`，并进行 HTML 转义。

### 不采用：解析普通文本中的 `tokens used`

旧日志曾出现过 `tokens used` 文本，但它依赖 CLI 的交互式输出格式，当前运行器还会丢弃 stdout。继续解析该文本会受 CLI 版本、语言和输出顺序影响，不能作为生产指标。

### 不采用：增加独立 API 计费或遥测接口

该方案会引入新的认证、计费口径和外部依赖，超出“在现有生成任务中显示真实用量”的范围。当前 CLI 已提供结构化事件，因此不需要扩大权限边界。

## 邮件呈现

当前 HTML 邮报的标题和日期版次位于 `<header>` 中。元数据模块在第一个 `</header>` 之后、第一篇正文栏目之前插入一行：

```html
<p class="meta brief-model-note" style="margin:2px 0 0;font-size:11px;color:#98a2b3;">
  注：生成模型 gpt-5.6-luna · 本次总用量 123,456 tokens
</p>
```

如果某封合法 HTML 邮报没有 `<header>`，则退回到第一个 `</h1>` 之后；再没有标题时退回到 `</body>` 之前。找不到任何 HTML 插入点时，元数据步骤失败并阻止发送，避免在无法满足用户要求时静默投递不完整结果。注释带固定 class，重复执行时替换现有注释而不是追加重复行。

## 组件与数据流

1. `scripts/run-daily-brief.sh` 为初稿和每次修复调用分别建立私有 JSONL 临时文件，并传入 `--json`。
2. 校验循环保持现状；只有完整邮报通过质量校验后，才调用元数据模块。
3. `src/daily_brief_agent/generation_metadata.py` 提供 JSONL usage 汇总、HTML 注释注入和命令行入口；生产 VPS 使用同等功能的根目录脚本副本。
4. 元数据模块输出一条不含原始事件内容的诊断行，例如 `generation_metadata=model=... total_tokens=30 usage_source=codex_json`。临时事件文件不归档、不进入 Git、不随邮件发送。
5. 元数据注入成功后，原有 SMTP 发送、dry-run 和发送结果验收流程继续执行；注入失败则返回明确错误且不发送。

## 测试与验收

- 单元测试覆盖：多次调用的 `total_tokens` 汇总、缺少 total 时的 input/output 回退、无 usage 时的不可得状态、HTML 转义、标题区插入位置、重复注释替换和 Subject 保留。
- 运行器回归测试覆盖：初稿失败后修复成功时将两次调用用量相加，并在最终正文中只有一条注释；SMTP 仍只在质量校验和元数据注入成功后调用。
- 本地验证运行全量 Python 测试、Shell 语法检查和隐私扫描；不得产生真实 SMTP 发送。
- VPS 部署前建立新的只读可回滚备份目录；部署后运行 Python 编译、元数据 fixture、runner dry-run 和配置/定时器回读，确认日志出现模型与总量字段且正文标题后只有一条浅色注释。实际发送由定时任务按原计划完成，不用手工补发。

## 失败与安全边界

- Codex 调用失败、质量校验失败或修复耗尽：沿用现有失败路径，不发送。
- JSONL usage 缺失但正文有效：允许发送，但注释明确标为“暂不可得”，日志记录 `usage_source=unavailable`。
- HTML 插入点缺失、输入输出文件无法读写或元数据模块异常：阻止发送并保留受限权限的失败稿，方便排查。
- 元数据字符串全部按 HTML 文本转义；不将事件流、提示词、密钥、邮箱地址或正文副本写入公开仓库。
